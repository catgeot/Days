## 1. 목표

게시가 끝났고 권리·출처·영상 URL·장소 매핑이 모두 확인된 자체 mp4만, 새 세로 피드에서 재생해요. 화면에 보이는 영상 하나만 재생하고, 기본은 음소거이며 사용자가 소리를 켤 수 있어요. 모바일은 `playsinline`으로 재생해요. 재생이 실패하면 표지와 「다시 시도」를 보여요. 같은 편이 다시 실패하면 「다음 영상」 버튼을 보여주고, 사용자가 누를 때만 그 편으로 이동해요. 출처와 공공누리 표기는 항상 보여요. 확인된 장소는 모두 기존 장소 상세로 이어져요.

플래그 기본값은 꺼짐이에요. 홈과 검색은 그대로예요. 일반 공개, 운영 DB 쓰기, R2 쓰기와 신규 유료 자원 생성은 사이트 기획 채팅의 별도 승인 없이 하지 않아요.

## 2. 최소 범위

| 넣어요 | 넣지 않아요 |
|---|---|
| 자격 네 가지가 모두 확인된 편만 | 칩, 필터, 좋아요, 로그인, 추천 알고리즘 |
| 세로 스크롤 피드, 가시 영상 1개만 재생 | YouTube·Shorts·Mux·새 외부 업체 |
| 기본 음소거, 사용자 조작으로만 음소거 해제 | 홈 창, 축제 허브 가로줄, 검색 결과 노출 |
| `playsinline`, 다시 시도, 사용자가 누르는 「다음 영상」 | 임의 slug, 미확인 장소 링크, 「확인 대기」칩, 실패 후 강제 스크롤 |
| 출처·공공누리 문구 | 새 DB 스키마, 운영 INSERT |
| 확인된 장소 상세 버튼(기존 `/place/:slug`) | R2 업로드, 버킷 생성, 서명 URL |
| 플래그 기본 OFF, 미리보기와 390/1280 캡처 | sitemap·홈 바로가기·릴리스 노트 |

확인된 장소는 개수와 관계없이 데이터에 모두 남겨요. 장소가 많다는 이유만으로 그 편을 빼지 않아요. 카드 안에 같은 스타일의 장소 링크를 순서대로 쌓고, 링크가 카드 높이를 넘으면 카드 안에서만 스크롤해요. 피드의 스냅 위치는 그대로예요. 칩이나 필터는 만들지 않아요. 확인된 장소가 한 곳도 없는 편은 공개 목록에 넣지 않고 공개 보류로 남겨요.

한 페이지 안에서 재생 실패나 장소 선택만으로 피드를 강제 이동하지 않아요. 내부 활성 인덱스와 보이는 스냅 항목은 항상 같아야 해요. 둘을 바꾸는 동작은 사용자의 「다음 영상」 또는 직접 스크롤뿐이에요.

소리 상태는 다음 편으로 넘기지 않아요. 모든 편은 다시 음소거로 시작해요.

- `getKoglReels`를 화면에서 import하는 파일은 없어요. 참조는 `koglReels.js`, `scripts/kogl-reels.test.mjs`, 플래그 정의뿐이에요.

- 장소 재생은 `src/components/PlaceCard/views/YouTubePlayerView.jsx`의 YouTube iframe이에요. 라우트는 `src/App.jsx`의 `place/:slug`와 `place/:slug/:tab`이에요.
- 알 수 없는 경로는 `src/App.jsx`의 `path="*"`가 `/`로 보내요.

- 캡처 선례는 `e2e/stay-card-image-link-iceland-live.spec.js`예요. `viewport`와 `page.screenshot({ clip })`로 390과 1280을 찍어요. `AGENTS.md`는 390 캡처의 PNG 너비를 390px로 고정해요. `deviceScaleFactor: 1`, `locator.screenshot()`은 쓰지 않아요.
- 짧은 QA 링크는 `src/shared/cloudPreview/cloudQaShareLinks.js`와 `vercel.json` `redirects`가 한 쌍이에요. 여기 있는 리다이렉트는 `main`에 들어가면 `www.gateo.kr`에 적용돼요.

## 5. 설계 결정

세션이 같은 결정을 반복하지 않도록 여기 고정해요.

1. 새 플래그 이름은 `VITE_GATEO_SELF_REELS`예요. `'1'`만 켜요. 기존 `VITE_GATEO_KOGL_REELS`와 `VITE_GATEO_REELS_BASE_URL`은 그대로 두어요. 그 플래그는 연결되지 않은 10건 목록용이고, 장소 경로도 이번 자격 조건과 달라요.
2. 픽스처 플래그는 `VITE_GATEO_SELF_REELS_FIXTURE`예요. 본 플래그가 켜져 있을 때만 의미가 있어요. 공유 미리보기 빌드에는 넣지 않아요. 단위 테스트·로컬 캡처에서만 켜요.
3. 경로는 `/reels` 하나예요. `/reels/:reelId`는 이번 범위 밖이에요.
4. 플래그가 꺼지면 라우트를 등록하지 않아요. 그러면 기존 `*`가 `/`로 보내요. 홈 번들에 페이지를 넣지 않아요.
5. 운영 목록의 시작값은 빈 배열이에요. 공개 목록에 들어가려면 권리 확인, 공공누리가 들어간 출처 문장, 서명·만료 쿼리가 없는 `https` 영상 URL, 장소 경로 1개 이상이 모두 있어야 해요. 장소 경로 상한은 없어요. 확인된 경로는 빠짐없이 보존해요. 장소가 0곳이면 그 편은 공개 보류예요. 권리·출처·영상 URL이 없으면 공개 목록에서 빠져요. `KOGL_REELS_RAW`는 import하지 않아요.
6. 테스트 픽스처와 운영 목록은 파일이 달라요. 픽스처 id는 `fixture-`로 시작해요. 첨부 표의 지명·slug·편 번호를 픽스처에 쓰지 않아요. 픽스처 영상은 테스트가 응답으로 넣는 최소 mp4예요. 서명 URL과 운영 호스트를 소스에 적지 않아요.
7. 플레이어는 새 페이지 컴포넌트의 `<video muted playsInline>`이에요. `YouTubePlayerView.jsx`는 수정하지 않아요.
8. 장소 링크는 기존 장소 라우트예요. 새 장소 데이터는 만들지 않아요. 픽스처 단위 테스트는 네트워크 없이 `href`와 버튼 개수를 봐요. 공개 검토의 실편 동선은 그것만으로 통과하지 않아요. 세션 6에서 실영상이 재생되고, 버튼을 눌러 의도한 장소 상세가 열리는지 읽기 전용으로 확인해요.
9. 재생이 두 번 실패해도 스크롤과 활성 인덱스를 바꾸지 않아요. 다음 편이 있으면 「다음 영상」을 보여주고, 그 클릭에서만 스크롤과 인덱스를 함께 옮겨요.
10. 페이지에는 `noindex`를 넣어요. `vite.config.js`의 `koreaRoutes`, `scripts/generate-sitemap.cjs`의 허브 목록, 홈 바로가기, 검색 색인에는 `/reels`를 넣지 않아요.
11. `www.gateo.kr/qa/...` 단축 링크는 공개 검토가 끝난 뒤의 별도 합의예요. 세션 1~6에서 `vercel.json` 리다이렉트와 `cloudQaShareLinks.js`를 바꾸지 않아요. 그 파일은 프로덕션 라우팅이에요.
12. 기존 `koglReels.js`와 `scripts/kogl-reels.test.mjs`는 삭제하거나 10건 계약을 바꾸지 않아요.
13. 담당은 사이트 기획이에요. 세션을 열고, 결과를 검수하고, 공개 여부를 묻는 곳도 사이트 기획 채팅이에요. 사이트 관리 채팅으로 이 페이지의 구현이나 공개 승인을 넘기지 않아요.

## 6. 세션을 나눈 이유와 소요

첨부 실행안은 작업 블록을 PR-A 2~3일, PR-B 1~1.5일, 합계 약 3~4.5일(추정)로 적었고 착수일은 확정하지 않았어요. PR-B 옆에는 매핑 대기를 그 일수 밖으로 적어 두었고, R2에 올린 기록·공개 URL·파일 존재는 미확인이라고 이미 적혀 있어요. 그 3~4.5일을 영상 URL이 확인된 뒤의 일정으로 읽지 않아요.

이번 문서는 그 달력 추정을 다른 날짜로 바꾸지 않아요. 저장소에 라우트와 `<video>` 플레이어와 영상 파일이 없는 점을 보고, 검수할 수 있는 세션으로 다시 나눈 거예요. 아래 시간은 코드 작업량 추정이에요. 사이트 기획 검수 대기, 호스팅, 권리, 자료 대기는 포함하지 않고, 완료일을 약속하지 않아요.

구현은 사용자 기본 상위 모델이고, 점검 명령과 캡처만 Composer 서브에이전트가 해요. 이 계획 실행과 이번 문서 수정에서는 둘 다 돌리지 않아요.

시간 근거예요.

- 세션 1은 `gateoFeatureFlags.js`와 `App.jsx`에 있는 플래그·조건부 라우트를 복제하는 분량이고, 빌드 1회를 포함해요.

- 세션 3은 JSX에 `<video>` 선례가 없어 가장 길어요. 픽스처 응답만 써요.
- 세션 4는 세션 3 화면에 실패 상태, 「다음 영상」, 출처, 장소 목록을 더해요.
- 세션 5는 기존 e2e의 `clip` 캡처 방식으로 빈 목록 2장과 픽스처 2장을 찍어요. 미리보기 배포를 허용할지는 이 시간에 넣지 않아요.
- 세션 6의 목록 반영은 확인 패키지 행을 카탈로그로 옮기는 편집이에요. 편당 20–40분은 실영상 재생, 장소 버튼마다의 상세 진입, 피드 390·1280 캡처를 읽는 시간이에요. 확인된 편 수가 저장소에 없어서 편당 시간만 적고 총합은 패키지 이후에 곱해요.

코드 작업 합계(세션 1~5, 대기 제외): 60–120 + 45–90 + 180–300 + 120–180 + 120–180 = 525–870분(약 8시간 45분–14시간 30분, 추정).

세션 6 코드는 그 합계 밖이에요. 자료가 준비된 뒤 목록 반영 60–90분에, 확인된 편 수 × 20–40분을 더해요.

대기(기간 추정 없음): 권리·출처 확인, 서명 없는 안정 영상 URL, 장소 1곳 이상, 그 URL의 읽기 허용, 호스팅, 미리보기 배포 허용, 사이트 기획의 세션 검수. 원안도 매핑·호스팅 확인을 작업 일수 밖으로 두었어요.

## 7. 세션마다 사이트 기획에게 넘기는 것

매 세션 끝에 아래 다섯 가지를 채팅과 일지에 남겨요. 없는 항목은 「없음」이라고 적고, 추측으로 채우지 않아요.

1. 변경 요약: 파일 목록, 플래그 기본값, 홈·검색·sitemap을 건드렸는지.
2. 테스트 로그: 실행한 명령, 마지막 PASS/FAIL 줄, 건너뛴 검사와 이유.
3. 미리보기: 세션 5 이전에는 「공유 URL 없음」. 세션 5 이후에는 실제 git Preview URL. 배포 해시 URL은 적지 않아요.
4. 캡처: 세션 5·6만. 파일 경로, 가로 픽셀, 빈 목록인지 픽스처인지 실편인지. 세션 5 캡처는 공개 완료 자료가 아니에요.
5. 미확인: 다음 세션을 막는지 여부.

Composer 서브에이전트는 이 다섯 가지를 모으는 점검만 해요. 사이트 기획 검수를 통과로 바꾸지 않아요. 브라우저는 사이트 기획이 명시하기 전에는 `computerUse`로 누르지 않아요.

공통 중단: 같은 실패를 두 번 고친 뒤에도 그대로면 패치를 멈추고 원인·시도·선택지를 보고해요. 칩·필터·좋아요·로그인·추천, R2 쓰기, 서명 URL, 운영 DB 쓰기, 첨부 표의 slug 생성, 홈·검색 동작 변경이 필요해 보이면 그 세션을 멈춰요.

공통 되돌리기: 그 세션 커밋을 feature 브랜치에서 `git revert`해요. `main`에는 올리지 않아요. 플래그 기본 OFF라서, 실수로 코드만 들어가도 환경값 `'1'`이 없으면 페이지는 열리지 않아요. 그래도 머지는 사이트 기획 장부 확인 전으로 두지 않아요.

## 11. 세션 4 — 실패와 장소

채팅명: `자체 릴스 #4, 실패와 장소`

범위: 재생 오류면 표지(없으면 빈 프레임)와 「다시 시도」를 보여요. 화면과 활성 인덱스는 그 편에 머물러요. 같은 항목이 다시 실패하면, 다음 편이 있을 때만 「다음 영상」 버튼을 보여요. 그 버튼을 누르기 전에는 스크롤하지 않아요. 누르면 그 다음 편으로 스크롤하고 활성 인덱스를 같은 값으로 바꿔요. 마지막 편이면 실패 화면에 남고 다음 버튼은 없어요. 출처 문장은 활성 카드에 항상 보여요. 확인된 장소 링크는 카드 안에 모두 보여요.

수정 후보:

- `src/pages/SelfReels/selfReelsPlayback.js`
- `src/pages/SelfReels/SelfReelsFeed.jsx`
- `scripts/self-reels-playback.test.mjs`
- `e2e/self-reels-feed.spec.js`

의존성: 세션 3 피드. 장소 페이지 구현에는 의존하지 않아요.

완료 기준:

- 오류 한 번은 다시 시도 상태이고, 스크롤 위치와 활성 인덱스가 그대로예요.
- 두 번째 오류도 화면을 옮기지 않아요. 다음 편이 있으면 「다음 영상」이 보여요.
- 「다음 영상」을 누른 뒤에만 스냅 대상과 활성 인덱스가 함께 다음 편이 돼요. 누르기 전에 둘 중 하나만 바뀌면 실패예요.
- 출처가 없는 항목은 세션 2 자격에서 이미 빠져요. 피드 테스트의 보이는 카드에는 출처 문장이 있어요.
- 픽스처 테스트는 네트워크 없이, 장소 링크 개수와 각 `href`가 `placePaths` 전체와 같은지만 봐요. 장소 상세가 열리는지는 세션 6의 실편 동선이에요.

예상 소요: 2–3시간(추정). 세션 3 검수 다음이에요. 완료 후 세션 5로 가요.

중단/되돌리기: 실패 뒤 자동으로 다음 편을 스크롤하거나, 인덱스만 바꾸고 화면을 두지 않거나, 장소 개수로 편을 빼면 세션 4 커밋을 revert해요.

사이트 기획에 넘기는 결과: 실패 후 화면이 그대로인지, 「다음 영상」 클릭 뒤에만 이동하는지, 픽스처 `href` 목록, 테스트 로그, 공유 미리보기 없음, 캡처 없음, 미확인(실편 장소).

## 12. 세션 5 — 미리보기 캡처

채팅명: `자체 릴스 #5, 미리보기 캡처`

범위: 플래그를 켠 빌드의 빈 운영 목록과, 로컬 픽스처 피드의 재생 화면을 390과 1280으로 찍어요. 공유 git Preview는 사이트 기획이 그 브랜치의 미리보기를 허용한 뒤에만 켜요.

완료 기준:

- 플래그를 끈 빌드에서 `/reels`는 `/`로 가요.
- 홈과 검색 스펙을 새로 깨지 않아요. 이 세션은 홈 화면을 수정하지 않아요.

점검:

```bash

npx playwright test --config=playwright.config.self-reels.js
npm run build
```

캡처 명령은 스펙 안에 두고, 출력 경로를 일지에 적어요. 가로 픽셀은 `file` 또는 이미지 헤더로 확인해요.

예상 소요: 2–3시간(추정). 세션 4 검수 다음이에요. 로컬 캡처 시간만 포함해요. 미리보기 배포 허용은 대기라서 이 시간에 넣지 않아요. 허용이 없으면 URL 없이 캡처만으로 세션을 닫고, 그다음은 확인 패키지가 생긴 뒤의 세션 6이에요.

중단/되돌리기: 캡처 너비가 390이 아니거나, 픽스처 영상이 공유 미리보기에 보이면 배포 허용을 유지하지 않아요. `deploymentEnabled`를 다시 `false`로 되돌리고 세션 5의 화면 커밋을 revert해요.

사이트 기획에 넘기는 결과: 변경 요약, 테스트·빌드 로그, git Preview URL 또는 「미발급」, 캡처 4장의 경로와 가로 픽셀, 미확인(실편·호스팅). 이 캡처는 빈 목록과 픽스처 검수 자료예요. 공개 완료로 보지 않아요.

## 13. 세션 6 — 확인편 연결

채팅명: `자체 릴스 #6, 확인편 연결`

범위: 사람이 만든 확인 패키지에 있는 편만 운영 목록에 넣어요. 패키지가 없으면 파일을 만들지 않고 세션을 열지 않아요.

확인 패키지 위치는 `plans/self-reels-confirmed.md`예요. 세션 6이 그 파일을 코드로 옮기기 전에 사이트 기획이 각 행에 아래를 적어요.

- id
- 출처 문장(공공누리 포함)
- 권리 확인
- 안정 `https` 영상 URL (서명·만료 쿼리 없음)
- 장소 경로 전체. 개수 제한은 없어요. 0곳이면 그 행은 공개 보류예요
- 각 경로를 장소 상세로 연 기록

이 계획 실행은 그 파일을 만들지 않아요. 공개 가능한 행이 0이면 세션 6은 착수하지 않아요.

수정 후보:

- `src/pages/SelfReels/selfReelsCatalog.js` (패키지와 같은 행만)
- `scripts/self-reels-catalog.test.mjs`
- 세션 5 캡처 스펙의 운영 목록 케이스
- `plans/self-reels-confirmed.md`는 문서 PR로만 갱신

의존성: 세션 5 검수 다음이고, 확인 패키지가 있어야 해요. 둘 중 하나라도 없으면 열지 않아요. 영상 URL이 실제로 응답하는지는 업로드가 아니라 읽기 확인이에요. 읽기 승인 전이면 URL을 코드에 넣지 않아요. R2 설정 변경은 이 세션에 없어요. 호스팅이 서명 URL뿐이면 그 편은 공개 보류예요.

완료 기준은 두 층이에요.

픽스처·단위 테스트 (네트워크 없음):

- 코드의 운영 목록 길이가 패키지의 공개 행 수와 같아요. 장소 0곳과 권리·출처·URL이 없는 행은 빠지고, 이유만 일지에 남아요.
- 장소가 여러 곳인 행은 경로를 모두 가져요.
- 픽스처 테스트와 운영 목록 테스트는 서로 import하지 않아요.
- `href`가 같다는 결과만으로 이 세션을 통과로 보지 않아요.

실편 동선 (공개 검토에 필요, 읽기 전용):

- 플래그를 켠 미리보기에서 해요. DB 쓰기, R2 업로드, 좋아요, 로그인은 없어요.
- 확인된 편마다 영상이 실제로 재생되는지 봐요. `paused`가 아니고, `currentTime`이 움직이거나 `playing`이 나와야 해요. 음소거는 켠 채로 확인해도 돼요.
- 확인된 장소 버튼마다 클릭해서, 주소가 그 경로로 바뀌고 장소 상세 화면이 열리는지 봐요. 속성 문자열만 읽고 끝내지 않아요.
- 실편 피드 캡처는 가로 390과 1280이 각 1장이에요. 390 파일 너비는 390px예요. 첫 장소 상세도 같은 두 너비로 1장씩 남겨요. 나머지 장소는 클릭 후 최종 경로를 로그에 적어요.
- 재생이 안 되거나 상세가 다른 장소로 열리면 그 편은 공개 보류로 되돌리고, 빈 목록·픽스처 캡처로 대신하지 않아요.

점검: `npm run test:self-reels`, `npm run build`. CI 기본 명령은 실영상을 호출하지 않아요. 실편 읽기는 사이트 기획이 읽기를 허용한 URL만, 기본 테스트와 따로 해요.

예상 소요: 확인 패키지가 있는 뒤에만 목록 반영 60–90분(추정), 실편 1개당 읽기 검증 20–40분(추정). 패키지·호스팅·권리 대기의 길이는 적지 않아요. 이 세션이 끝나야 공개 여부를 사이트 기획 채팅에 올려요.

중단/되돌리기: 패키지와 다른 행, 서명 URL, 장소가 많다는 이유만으로 편을 삭제, 실편 재생 없이 `href`만으로 통과 처리가 되면 목록 커밋을 revert해요. 호스팅 작업으로 세션을 확장하지 않아요.

사이트 기획에 넘기는 결과: 패키지 행 수와 코드 행 수, 보류 이유, 단위 테스트 로그, 편별 재생 여부와 장소 클릭 후 경로, 미리보기 URL, 실편 390·1280 캡처 경로와 가로 픽셀, 아직 확인되지 않은 호스팅 항목.
