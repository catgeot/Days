## 1. 현재 구조 (오해 방지)

홈 하단 5칩 (`paradise` · `nature` · `urban` · `culture` · `adventure`)은:

- **지구본 5면 지리 권역 UX** (면당 나라 배타 · [`globeFaceRegions.js`](../src/pages/Home/lib/globeFaceRegions.js))
- **≠** `TRAVEL_SPOTS.categories` 테마 필터의 “해안 모아보기”

`.ai-context` 명시: 나라 칩 권역을 `primaryCategory`/휴양지로 재배치하지 말 것.  
→ 「해안·해양」을 **6번째 카테고리 ID**로 넣으면 면 분할(72°×5)·카메라·나라 배타가 깨짐.

`categories` 배열은 별도 테마 태그(다중 허용, 현재 multi-cat **95**/273). 여기에도 `coast`/`marine` 값은 **없음**.

## 3. 필드로 채우면 구분 가능한가?

### 3.1 현재 필드

필수·상용: `slug`, `name`, `name_en`, `lat`/`lng`, `country`, `tier`, `continent`, `categories`, `primaryCategory`, `denseRegion`, `desc`, `keywords` …

| 후보로 쓸 수 있는 것 | 한계 |
|---------------------|------|
| `categories` + paradise | 휴양≠해안(내륙 리조트·일부 도시 혼입) · 해양명 없음 |
| `continent: oceania` | 태평양 섬에 치우침 · 에게해·아드리아 미커버 |
| `denseRegion == null` | 섬·단독에 자주 쓰이나 해안 전용 아님 (198건) |
| `desc`/`keywords` | 비정규 · 오탐 · 해양명 누락 |

**판정**: 현 필드만으로 해안/해양 **신뢰 구분 불가**. 새 SSOT 필드(또는 overrides→generate)가 필요.

### 3.2 제안 스키마 (최소)

스팟 단위 (overrides → generate 패턴 권장, `travelSpots.js` spots 직접 난타 금지):

```text
coastKind: null | 'island' | 'archipelago' | 'coastal-city' | 'reef' | 'peninsula'
seaIds: string[]          // 예: ['aegean','mediterranean'] — 다중 가능(보스포루스 등)
seaPrimary: string | null // 칩·필터 기본 1개
```

해역 카탈로그 SSOT (신규, 예: `seaBasins.json` + overrides):

```text
id, name, name_en, parentOcean, bbox | polygonHint, center{lat,lng}, tier, aliases[]
```

| 층 | 예 | 역할 |
|----|-----|------|
| **대양** (소수) | 태평양·대서양·인도양·북극해·남극해 | 광역 진입 · 너무 넓어 “숨은 섬” 탐색엔 부적합 |
| **주변해** (본게임) | 에게해·산호해·안다만해·술루해·반다해·아드리아해·홍해… | 한 칩에 핀 3~15 → 탐험 밀도 적정 |
| **스팟** | 산토리니·미코노스·로드스… | 기존 travelSpots |

### 3.3 채움 전략 (품질)

1. **수동 시드 1차** — 해안 후보 ~80을 `coastKind`+`seaPrimary` 큐레이션 (휴리스틱 초안 → 사람/에이전트 검수).
2. **해역 카탈로그 25~40개** — IHO 주변해 중 **여행 핀이 2개 이상 붙을 수 있는 것**만 (빈 칩 금지).
3. **좌표 bbox 보조** — 초안만 · 최종은 수동 확정 (국경·내해·하구 오탐 방지).
4. **audit** — `seaIds` orphan · 해역당 스팟 0 · paradise-only와 과도 중복 리포트.

자동만으로 “산호해”를 채우면 GBR·뉴칼레도니아·솔로몬이 한 바구니에 섞이거나 빠짐 → **오케 배치 가능한 큐레이션 작업**으로 보는 것이 맞음.

## 4. 이 탐색이 어떻게 도움이 되나

### 4.1 지금 막혀 있는 UX

```
나라/권역 칩 → 유명 국가·도시
테마(휴양)   → 리조트·낙원 뭉치
검색         → 이미 아는 지명만
```

생소한 **해양명 → 그 바다에 떠 있는 섬** 경로가 없음.

### 4.2 제안 UX (5칩 유지 · 별칭/2차 축)

```
[기존 5면] Paradise / Nature / …
        └─ (옵션) 「해안·해양」토글 또는 면 하단 2단 칩
              └─ 주변해 칩: 에게해 · 산호해 · 아드리아 · …
                    └─ 해당 seaIds 스팟만 강조 / 카메라 center
```

| 가치 | 설명 |
|------|------|
| **발견** | “에게해”만 알아도 크레타·보드룸·(미등록 시) 히오스·사모스 후보로 확장 |
| **숨은 섬** | 산호해·술루해·반다해처럼 국가 브랜드가 약한 해역 = 니치 섬 노출 |
| **5면 보존** | 대분류 불변 · 나라 배타·카메라 SSOT 유지 |
| **검색 별칭** | `KEYWORD_SYNONYMS`/`THEME_DB`에 해양명 → 해역 또는 대표 스팟 (단기 가능) |
| **낙원과 차별** | paradise=경험 톤 · 해양=지리 컨테이너 (갈라파고스=adventure+marine 병행) |

### 4.3 “별칭”의 의미 (제품 선택지)

| 옵션 | 내용 | 추천 |
|------|------|------|
| **A. 검색·동의어만** | 에게해→기존 스팟 매핑 | 빠름 · 숨은 섬 발견력 약함 |
| **B. 해역 2차 칩** (권장) | 5칩 아래/옆에 해양 칩 · `seaIds` 필터 | 발견력↑ · 5면 비파괴 |
| **C. paradise 라벨을 해안로 개명** | 카피만 변경 | **비추천** — 면 권역(아시아·남태평양)≠전 세계 해안 |
| **D. 6번째 대분류** | GLOBE_CATEGORY_IDS 확장 | **비추천** — 5면·72°·나라 배타 전면 재설계 |

권장: **B + A 병행**. UI는 합의 전 구현 금지(§4.1 5).

### 4.4 명소 세권 칩과의 유사성

국내 명소 [`korea-scenic-mid-cluster-plan.md`](./korea-scenic-mid-cluster-plan.md)와 같이:

- 대분류는 유지
- **중분류(해역)** 로 목록·카메라 밀도 조절
- 빈 중분류 칩 비노출

### 4.5 Mapbox에 이미 보이는 해역명 — 칩과 역할 분리

지구본은 줌에 따라 **대양·만·해** 라벨을 이미 그림 (멕시코만 · 사르가소해 · 바렌츠해 · 더 작은 만/해협도 확대 시).  
이건 **지도 지명(수동 읽기)** 이지, gateo **탐험 칩(능동 필터)** 이 아님.

| | Mapbox 물 라벨 | 해안·해양 칩 (gateo) |
|--|----------------|----------------------|
| 출처 | 스타일/타일 전 세계 | 큐레이션 `seaBasins` + `seaIds` 스팟 |
| 개수 | 수백~ | **뷰당 3~8 · 전역 시드 25~40** |
| 탭 | 바다 클릭 = uiPlace/근처 curated (스냅 금지) | 해역 선택 → 그 바다 섬·연안 핀 강조·카메라 |
| 빈 여행지 | 사르가소해·바렌츠해도 **이름만** 뜸 | 스팟 **&lt;2면 칩 숨김** |
| 목적 | “여기가 무슨 바다인지” | “이 바다로 갈 만한 여행지” |

**원칙**: 지도에 보인다고 칩으로 다 올리지 않음.  
사르가소해(거의 무인도)·바렌츠해(극지·크루즈 니치)는 **라벨로만 두고**, 칩은 **여행 핀이 붙는 해역**만.

### 4.6 칩을 어떻게 보여줄지 (권장 UX)

**권장 = 나라 레일 「바다」모드 + 뷰포트 근처 해역만**

지금 구조: `5면 카테고리` → (소권역) → **나라 칩 레일**.  
여기에 레일 상단(또는 나라 목록 헤더)에 **토글 2개**만 추가하는 형태가 톤 침입이 가장 적음.

```
[ 나라 | 바다 ]     ← 기존 레일 자리 재사용 (칩 줄 추가 최소화)
  바다 ON 일 때:
    · 현재 카메라/면 근처 seaBasins 3~8개만 칩
    · 탭 → fitBounds(해역) + seaIds 스팟 하이라이트
    · 스팟 0~1개인 해역은 목록에서 제외
```

| 단계 | 보이는 것 | 예 |
|------|-----------|-----|
| 줌 낮음·전역 | 대양·큰 주변해 중 **시드+스팟≥2** 만 | 카리브 · 지중해 · 산호해 |
| 면/소권역 고정 | 그 면 bbox에 걸친 해역 | culture 면 → 에게·아드리아·티레니아 |
| 확대·팬 | **뷰포트 교차** 해역으로 칩 교체 | 멕시코만 근처면 그 칩만 부상 |
| 더 작은 만·해협 | 칩 **안 함** · Mapbox 라벨만 | 사르가소 · 작은 만 이름 |

**보조 (나중)**: Mapbox 물 라벨/바다 클릭 시  
이름 ↔ `seaBasins.aliases` 매칭되면 → 자동으로 「바다」모드 + 해당 칩 활성.  
매칭 실패(사르가소 등) → 지금처럼 바다 uiPlace (칩 폭주 방지).

**비권장**

| 안 | 이유 |
|----|------|
| 하단 5칩 옆에 「해안」6번째 | 5면·72°·나라 배타 붕괴 |
| 전 세계 해역 칩 스크롤 수십 개 | 나라 칩보다 더 산만 · 빈 바다 많음 |
| Mapbox에 보이는 이름을 전부 칩 동기화 | 사르가소·바렌츠·소만까지 제품 노이즈 |
| 나라 칩과 해역 칩 동시 두 줄 상시 | 모바일 하단·PC 레일 밀도 초과 (§4.1 UI) |

**카피**: 토글은 `나라` / `바다`(또는 `해역`). 「해안 칩」을 5테마와 동급 라벨로 쓰지 않음 — 해안은 **모드**, 칩 한 칸은 **구체 해역명**(에게해·산호해).

### 4.7 해역 tier (칩 노출 우선순위)

| tier | 대상 | 칩 |
|------|------|-----|
| 1 | 여행 밀도 높은 주변해 | 시드·상시 후보 (에게·카리브·산호해·안다만…) |
| 2 | 만·큰 내해 (멕시코만 등) | 뷰포트/면에 들어올 때만 |
| 3 | 극지·대양 한가운데·무인 해역 | **칩 제외** · 지도 라벨만 (바렌츠·사르가소·남극해 광역) |
| — | 작은 만·곶·해협 | 라벨만 · SSOT 불필요 |

멕시코만 = tier 2 (칸쿤·쿠바 축과 연결 시 칩 OK).  
사르가소해·바렌츠해 = tier 3 (보이되 고르지 않음).

## 5. 해역 시드 (1차 후보 · 빈 칩 제외 원칙)

여행 핀 2+ 기대되는 주변해부터:

| 권역 | 해역 id (안) | 기대 스팟 예 |
|------|--------------|--------------|
| 지중·유럽 | `aegean`, `adriatic`, `mediterranean`, `tyrrhenian` | 산토리니·크레타·흐바르·이비자·코르시카 |
| 인도양 연안 | `andaman`, `red-sea`, `arabian` | 안다만·푸켓·(홍해 리조트 보강 시) |
| 서태평·동남아 | `south-china-sea`, `celebes`, `banda`, `sulu`, `coral-sea`, `philippine-sea` | 팔라완·라자암팟·코모도·GBR·팔라우 |
| 대양주 | `tasman`, `coral-sea` | 시드니·GBR·뉴칼레도니아 |
| 미주 | `caribbean`, `gulf-of-mexico` | 칸쿤·바하마·(보강) |
| 대양 광역 | `pacific`, `atlantic`, `indian` | 진입용 · 세부 칩 없을 때만 |

**산호해**: GBR·뉴칼레도니아·바누아투·솔로몬 축 — 지금 desc에 고유명 거의 없음 → **필드 채움이 선행**되어야 칩이 의미 있음.

## 7. 사람 결정 (다음 세션 전)
